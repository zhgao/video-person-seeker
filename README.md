# 监控视频找人 v2.2

扫描**录好的**监控视频，自动找出"有人出现"的时间段，生成可点击跳转的网页报告。

v2 新增：**自然语言查询**（如"这两天谁在摘菜"）+ **多文件批量扫描** +
**弯腰（疑似摘菜）启发式检测** + 查询片段一键提取。
v2.1 新增：**本地网页版**（`python web_app.py`，见下）。
v2.2 新增：**两遍扫描**（默认开启：粗扫定候选 → 精扫确认，更快）+
**多进程并行**（`--jobs N`，多核加速）。

## 快速开始

环境要求：Python 3.9+（Windows / macOS / Linux 都可以）

```bash
pip install -r requirements.txt
```

### v1（单文件人物检测，保持不变）

```bash
python detect_people.py 监控录像.mp4
```

跑完后打开输出目录里的 **`report.html`**（双击用浏览器打开即可，不需要联网），
点击任意"有人片段"就会跳转播放。

### v2（自然语言查询 + 批量）

```bash
# 场景：菜园监控，想查"这两天谁在摘菜"
python detect_people.py 监控视频文件夹 --query "这两天谁在摘菜"
```

工具会：解析查询 → 按日期过滤视频文件 → 逐个检测 →
生成按日期分组的报告 → 把命中的片段合并提取为
`这两天谁在摘菜_提取.mp4`。

`--query` 也可以配合单个文件使用：
```bash
python detect_people.py 某段录像.mp4 --query "昨天有人摘菜吗"
```

## 网页版（推荐，不用记命令）

```bash
python web_app.py
```

浏览器会自动打开 http://127.0.0.1:8000（换端口：`python web_app.py --port 8123`）。
页面上三步：① 填**本机**视频文件夹路径（如 `D:\录像`）→
② 输入查询（默认"这两天谁在摘菜"）→ ③ 点"开始检测"。
填完路径会自动显示预估耗时；大文件可勾选 **⚡极速模式**（速度翻倍、精度略降）。
检测完报告直接嵌在页面里看，提取视频一键下载。

注意事项：
- 仍需 Python 环境 + `pip install -r requirements.txt`；服务和浏览器跑在同一台机器，不上传任何文件。
- 首次运行要下载 AI 模型（约十几 MB），请耐心等待。
- 文件夹路径填的是**本机路径**，不是上传——几个 GB 的录像不用拷贝，本地直接扫。
- 长视频（几小时）内存平稳：逐帧处理，不一次性载入；可在页面日志里看到实时进度。

## 查询示例

| 查询 | 解析结果 |
|---|---|
| 这两天谁在摘菜 | 最近2天，弯腰检测 |
| 昨天有人吗 | 昨天全天，人物检测 |
| 前天有没有人摘菜 | 前天全天，弯腰检测 |
| 今天谁在干活 | 今天全天，弯腰检测 |
| 本周谁来了 | 本周一~今天，人物检测 |
| 10月18日谁来了 | 10月18日全天，人物检测 |
| 2026-10-15有人吗 | 当天全天，人物检测 |
| 10月18日到10月20日谁摘菜了 | 日期范围，弯腰检测 |

动作关键词：出现 `摘菜 / 摘 / 弯腰 / 干活` 任一 → 弯腰检测模式；
只有 `有人 / 谁 / 人` → 人物检测模式。

## 参数

| 参数 | 说明 | 默认值 |
|---|---|---|
| `--query "…" ` | 自然语言查询（见上表）；目录模式下按日期过滤并自动提取 | 无 |
| `--dir` | 强制按目录模式处理第一个参数 | 自动判断 |
| `--mode` | auto=跟随查询（默认），person=人物，bend=弯腰 | auto |
| `--bend-angle` | 弯腰判定：躯干前倾角阈值（度） | 35 |
| `--bend-secs` | 弯腰判定：持续秒数阈值 | 3.0 |
| `--no-extract` | 关闭 `--query` 默认的片段提取合并 | 开启 |
| `--jobs N` | 并行进程数（多核加速）；设为 1 用单进程 | min(4, CPU核心数) |
| `--no-twopass` | 关闭两遍扫描，回退单遍全片检测 | 关闭（即默认两遍） |
| `--coarse-every N` | 粗扫抽帧间隔秒；调小减少漏检、调大更快 | max(2.0, every×4) |
| `--every N` | 每隔 N 秒抽一帧检测。N 越小越准、越慢 | 1.0 |
| `--conf X` | 置信度阈值。调低减少漏检，调高减少误检 | 0.5 |
| `--gap N` | 两次检测间隔超过 N 秒则算作两个片段 | 3.0 |
| `--out 目录` | 输出目录 | `<名>_找人结果` |
| `--reel` | （v1 单文件）剪出"只有人"的集锦视频（需 ffmpeg） | 关闭 |

输出目录里有：

- `report.html` —— 可点击跳转的报告（按日期分组 + 人物裁剪缩略图）
- `segments.json` —— 片段时间数据（可供二次开发）
- `thumb_*.jpg` —— 每个片段的人物裁剪缩略图（绿框标出检测到的人）
- `<查询>_提取.mp4` —— 查询命中的片段合并视频（需 ffmpeg）

## 文件日期判定规则（目录模式）

1. 先从**文件名**解析日期时间（支持 `20261018_093000`、`2026-10-18`、
   `10月18日`、`10-18` 等常见监控文件名格式）；
2. 文件名里没有日期 → 用**文件修改时间（mtime）**；
3. 只有落在查询日期范围内的文件才会被扫描。

建议：让录像文件名带上日期时间（如 `20261018_093000.mp4`），最准。

## 两遍扫描（默认开启）

长视频里"有人"往往只占一小段，全片逐帧检测很浪费。默认开启两遍扫描：

1. **粗扫**：按 `--coarse-every`（默认 `max(2.0, every×4)`，即 `every=1` 时每 4 秒一帧）
   全片只做**人物检测**（弯腰模式下粗扫也不跑姿态估计，省时间），找出候选区；
2. 候选区两端各外扩 `--coarse-every` 秒做 margin；
3. **精扫**：只在候选区内按 `--every` 跑完整检测（弯腰模式跑姿态判定）。

候选为空则直接结束，一帧精扫都不跑。

实测参考（30 秒测试视频，人物出现 20 秒，2 核 CPU）：
`--jobs 1` 两遍 33 秒 vs 单遍 22 秒——候选占比太大时两遍反而略慢；
它真正省时间的是"几小时录像里只有几分钟有人"的场景。

trade-off（请知悉）：**短于粗扫间隔的闪现可能漏检**
（比如两次粗扫抽帧之间只出现了 2 秒的人）。调小 `--coarse-every`
减少漏检、调大更快；`--no-twopass` 可彻底关闭，回退 v2 单遍行为。

`--every 2`（网页版"极速模式"）与两遍扫描可叠加，互不冲突。

## 多进程并行（`--jobs N`）

按时间把视频切成 N 段，每段一个 worker 进程独立跑两遍扫描，
命中回主进程统一按 `--gap` 合并。默认 `min(4, CPU核心数)`，`--jobs 1` 为单进程。

边界处理：每段向两侧扩展 overlap（≥ `max(bend_secs, gap, coarse_every) + every`）
再扫描——只靠 `--gap` 缝合在人物模式够用，但弯腰模式要求"连续 N 秒"，
横跨边界的弯腰会被切成两段而两边同时漏掉；overlap 让 worker 在扩展区内
看到完整动作，上报时只取自己区间的命中，主进程统一合并，
因此不断裂、不漏报、不重复。

注意：
- 每个 worker 独立加载模型（torch），多占几百 MB 内存；
  内存小的机器请调小 `--jobs`（如 `--jobs 2`）。
- 每个 worker 内 `torch.set_num_threads(2)`，避免"进程数×线程数"打满 CPU。
- worker 异常/模型加载失败会**显式报错并终止**，绝不静默丢数据。
- 跨平台一致用 spawn 模式（Windows 本来就只有 spawn）。

## 局限（请先读完再用）

- **弯腰检测是启发式**：用姿态估计算"肩-髋连线相对竖直方向的前倾角"，
  超过阈值且持续 `--bend-secs` 秒才算"疑似摘菜"。坐下、系鞋带、搬东西、
  镜头角度刁钻都可能误报；人太小、太暗、被遮挡会漏报。它是个筛查工具，
  不是裁判——最终请看缩略图和原视频确认。
- **不做人脸识别**："谁在摘菜"靠人物裁剪缩略图**人工辨认**，工具不会告诉你名字。
  真人脸识别需要提前录入人脸库，v2 没做。
- **只适用于录好的视频文件**（mp4 / avi / webm 等），不支持实时监控流。
- **速度参考**：默认每秒抽 1 帧，普通 CPU 上人物检测约每秒处理 5~15 帧，
  弯腰模式还要跑姿态估计，再慢约一倍。1 小时录像大约需要十几到几十分钟；
  赶时间可用 `--every 2` 翻倍提速，精度略降。
- **首次运行会自动下载模型**：yolov8n.pt（约 6MB，人物检测）；
  弯腰模式还会下载 yolov8n-pose.pt（约 6MB）。之后离线可用。
  姿态模型加载失败时会自动降级为纯人物检测并打印提示。
- `--query` 的提取合并需要系统安装 ffmpeg；没装会自动跳过，不影响报告。

## 原理

OpenCV 按固定间隔抽帧 → YOLOv8n 检测人物（COCO person 类）；
弯腰模式再用 YOLOv8n-Pose 取肩/髋关键点算躯干前倾角 →
连续的命中合并成片段 → 人物裁剪缩略图 → 按日期分组的可跳转报告 →
ffmpeg concat 提取合并。
